# Ανάπτυξη αλληλεπιδραστικού εργαλείου δημιουργίας δυναμικών και εξατομικευμένων εκπαιδευτικών παιχνιδιών

Το repository αυτό περιέχει το project της Διδακτορικής μου διατριβής

## Υλοποίηση

Αρχικά θα πρέπει να φτιάξω μία default σκηνη στην οποια θα ξεκινάει κάπου ο χρήστης και θα μπορεί να πηγαίνει πανω κατω δεξια και αριστερα, θα μπορεί να παίρνει items απο το πάτωμα, να αλληλεπιδρά με χαρακτήρες και μέρη και να προσπαθήσω να καθορίσω πως θα παλεύει. Μόλις φτιάξω την σκηνη θα φτιάξω μια δευτερη σκηνη που θα είναι το main menu. Εκεί θα ξεκινήσω να αυτοματοποιώ την δημιουργία της σκηνής παιχνιδιου.

Θα προσπαθήσω να ακολουθήσω τον οδηγό www.youtube.com/playlist?list=PLZ-54sd-DMALABr_k6VpMnut_11q2oJmv το οποίο χρησιμοποιεί δωρεάν assets https://pixelfrog-assets.itch.io/tiny-swords για να φτιάξει ένα 2D παιχίδι ρόλων. Δεν νομίζω να χρησιμοποιήσω το combat που φτιάχνει, αλλα θα ακολουθήσω την κίνηση και animations και ίσως το leveling σύστημα. Σκοπεύω να υλοποιήσω ένα turn based σύστημα μάχης https://www.youtube.com/watch?v=s-soSOYyUnc&list=PL0swe3EwWBiIHGT9pHYq7sQlOM2gTuZ7T αλλά δεν είναι σίγουρο. Επίσης δεν είναι σίγουρο οτι θα φτιάξω ένα tileset σύστημα για το κάθε επίπεδο γιατι θα πρέπει να μπορεί ο καθηγητης να φτιάξει το επίπεδο με μία εικόνα που θα δίνει ή αν φτιάξω tileset να μπορεί να δώσει μία εικόνα με tiles και να φτιάχνεται το επίπεδο μόνο του.

Το Input Map πιστεύω οτι θα το αφήσω στατικο, αλλά ίσως φτιάξω Keybinding Settings. Για τα animations πρεπει να βρούμε πως μπορουμε να προσθέσουμε ένα sprite στον χρήστη και μετά πως θα προσθέσουμε clips μέσα στον animation player βάζοντας keyframes.

Μπορώ να βασίσω το περιβάλλον μου σε ένα grid. Αυτό θα βοηθήσει τους καθηγητες στο να τοποθετουν πιο εύκολα τους χαρακτήρες, τα αντικείμενα και να φτιάχνουν τα περιβάλλοντα τους με τετράγωνα assets.

Η κίνηση στο grid θα πρέπει να είναι απαλή, στην ιστοσελιδα https://kidscancode.org/godot_recipes/4.x/2d/grid_movement/index.html χρησιμοποιεί ένα global tile size μαζί με tweens για να μεταφέρει τον χρήστη απο τον ένα grid tile στο άλλο με συγκεκριμένη ταχύτητα και να ελέγχει με raycasts αν θα πέφτει πάνω σε τοίχο.

Θα πρέπει να βρώ εναν τρόπο να μετατρέψω το tilemap που φτιάχνει το βιντεο https://www.youtube.com/watch?v=-kfBkdv8Z2E σε αυτοματοποιημένο tilemap. Δηλαδή ο καθηγητής να μπορεί να περιγράψει σε ένα αρχείο text πως θα είναι οργανωμένα τα tiles και τα layers τους, το collision τους και το που θα είναι ο χαρακτήρας, και το παιχνίδι να τα φτιάχνει αυτά στο runtime.

Πρόβλημα: Προσπαθώ να φτιάξω ένα tilemap layer κατα το τρέξιμο του παιχνιδιου, αλλα δεν εμφανίζεται. Όταν έχω φτιαγμένο το tileset απο πρίν όμως εμφανίζεται σωστά. Πρέπει να βρώ γιατι δεν είναι εμφανές όταν φτιάχνω το tileset μόνος μου.
Το tilemap layer το έφτιαξα, και μπορεσα να μετατρέψω ένα png sprite αρχεία σε ένα tilemap στο οποιο μπορω να τοποθετώ το sprite πανω σε ένα grid όσες φορές θέλω. Απο εδώ και πέρα θα πρέπει να βρώ αν θα μπορώ να βάλω επιπλέον layers οι οποίες μπορει να έχουν collision capabilities.

Μπορώ να τοποθετήσω layers πάνω σε άλλα layers και επίσης μπορώ να επιλέγω ποια κομμάτια grid να τοποθετώ αλλά εμφανίζεται θέμα στην τοποθέτηση collision.
Βρήκα τρόπο να εφαρμόζω collision στα σημεία του tileset που θέλω και λειτουργεί σωστά.
Φτιάξαμε και το θεμα του depth αλλάζοντας το y sort enabled σε true. Τώρα όταν ο χρήστης είναι πάνω απο τα βουνα εξαφανίζεται και όταν είναι κάτω ξαναεμφανίζεται.

Πρόσθεσα τώρα τρόπο να δημιουργείται η εμφάνιση και τα animations του χρήστη κατά το runtime. Ο χρήστης θα είναι ήδη δημιουργημένος στο project όμως δεν θα περιέχει κάποιο animation ή sprite. Κατά το τρέξιμο στοι αρχέιο text θα πρέπει να εμπεριέχεται το path για το sprite του χρήστη, τα Hframes και Vframes. Επίσης στο αρχείο θα πρέπει να υπάρχουν λεπτομέριες για κάθε animation: Αρχικά το όνομα της, ποιο component θα αλλάζει (με ονομα), ποιο property θα αλλάζει (με όνομα), απο τι value σε τι value θα το αλλάζει το property και πόσο θα διαρκεί. Χρησιμοποιώντας ένα συστημα tweens και ένα State Machine θα δημιουργούμε το animation μέσω tweens, θα το προσθέτουμε σε ένα Dictionary και όταν αλλάζει ο χρήστης απο το ενα state στο αλλο θα σταματάμε τα άλλα animations και θα ξεκινάμε αυτό που του αρμόζει για το state.

Τώρα θα πρέπει να μπορουμε να τοποθετουμε χαρακτήρες και αντικείμενα στο περιβάλλον και να φτιάξουμε πως θα κάνει interact μαζί τους ο χρήστης
Θα πρέπει τα αντικείμενα να έχουν sprites και area2d με τα οποια ο χρήστης θα χρησιμοποιεί το raycast του να βλέπει να βρίσκονται στον δρόμο του και αν είναι να μπορει να πατησει ενα κουμπί να στέλνει ένα message για interact. Φτιάξαμε ένα αντικείμενο με Area2D Collision το οποίο σταματάει τον χρήστη απο το να περάσει και όταν ο χρήστης πατάει προς την κατεύθυνση του λαμβάνουμε πίσω ενα reference του area2D του μέσω του raycast. Θα πρέπει τωρα να φτιάξουμε την δυνατότητα να στέλνει ο χρήστης signal μέσω του reference αυτού όταν πατάει κουμπί και να γίνεται έτσι το interaction.
Θα δημιουργούμε ένα raycast όταν τελειώνει το move ο χρήστης για να κανουμε ένα highlight στον χρήστη οτι μπορεί να κάνειο interact με το αντικείμενο μπροστά. Όταν θα πατάει το space θα δημιουργείται άλλο ενα raycast το οποιο θα κανει το interaction.
Φτιάξαμε signals με τα οποια ο χρήστης μπορεί να ενημερώσει το αντικέιμενο μπροστα του ότι το κοιτάει για να εμφανίσει label οτι μπορεί να γίνει interacted. Εάν ο χρήστης πατήσει το interaction κουμπί το αντικείμενο στέλνει ένα signal στον χρήστη να το προσθέσει σε ένα invetory array και αυτοδιαγράφεται.

Τώρα θα δημιουργήσουμε τους npcs. Αυτοί θα λειτουργούν όπως τα αντικείμενα, θα στελνουν δηλαδή ενημέρωση στον χρήστη οτι μπορούν να γίνουν interacted αλλά αφού κάνει interact ο χρήστης δεν θα διθαγράφονται, απλά θα ξεκινάει ο διάλογος που θα περιέχει ο χαρακτήρας. Οι χαρακτήρες θα είναι static body 2D έτσι ώστε να μπορούν να κινηθούν μόνοι τους αλλα να μην μπορούν να κινούν άλλα πράγματα. Μέσα στο script τους θα έχουν την δυνατότητα να εμφανίζουν text όταν τους πλησιάζει ο χρήστης για να δείξουν πως μπορούν να γίνουν interacted with και όταν γίνουν interacted θα ξεκινάει ο διάλογος. Όταν ξεκινάει ο διάλογος ο χρήστης δεν θα μπορεί να κινηθεί και θα ξεκινάμενα εμφανίζουμε το text του διαλόγου.

Αρχικά φτιάχνουμε το variable moveability που διαχωρίζεται απο το moving διοτι το moveability δειχνει στον χρήστη αν μπορεί να κάνει κινήσεις ενώ το moving εαν αυτη τη στιγμή κινηται. Δοκιμαστικά έφτιαξα ένα dictionary για τουσ διαλόγους των χαρακτήρων. Το dictionary έχει την αρχιτεκτονική:
[StartOfConversation[Word1[OPTION_1:Word2,OPTION_2:Word3]],
	Word2[Word4[OPTION_1:Word5,OPTION_2:Word6]],
	Word3[Word7[OPTION_1:Word8.OPTION_2:Word9]],
	Word5:ENDING_CONVERSATION,
	Word6:ENDING_CONVERSATION,
	Word7:ENDING_CONVERSATION,
	Word8:ENDING_CONVERSATION,
	Word9:GIVE_ITEM]
Η αρχιτεκτονική αυτή είναι φτιαγμένο σε json για να ταιριάζει με το πώς έχω φτιάξει το παιχνίδι και βασίζεται στην λύση: https://www.youtube.com/watch?v=eaNQkD1vX-E. Η ιδέα είναι πως το dictionary θα περιέχει λέξεις κλειδιά τις οποίες θα λέει ο χαρακτήρας, μέσα στις λέξεις κλειδιά θα περιέχονται επιλογές τις οποιες θα μπορεί να λέει ο χρήστης. Όταν επιλέξει μία επιλογή ο χρήστης θα πάμε σε αυτή την λέξη κλειδί που θα περιέχεται μέσα στο dictionary για να πάμε στην επόμενη πρόταση του χαρακτήρα η οποία είτε θα έχει κι άλλες επιλογές ή θα τελειώνει την κουβέντα. Για ΄τωρα δεν έχω φτιάξει το πώς θα επιλέγει ο χρήστης την απάντηση του, απλά επιλέγεται η πρώτη επιλογή κάθε 1.5 δευτερόλεπτα και έτσι τελειώνει μόνη της η κουβέντα. Κατα την διάρκεια του διαλόγου ο χρήστης δεν μπορεί να κινηθεί αλλα όταν τελειώνει ξανακουνιέται. Για να τελειώσει η κουβέντα το κείμενο που θα ακολουθεί μετά την λέξει πρέπει να είναι "ENDING_CONVERSATION" όμως εάν ο χαρακτήρας έχει αντικείμενο id που δεν είναι -1 και η τελευταία λέξη είναι GIVE_ITEM τότε ο χρήστης λαμβάνει ένα αντικείμενο με το ίδιο id.
Μπορούμε να κάνουμε το dictionary των διαλόγων να κρατάει περισσότερο απο έναν διαλόγους και να βάλουμε ένα dialogue counter μέσα στον χαρτακτήρα. Όταν ο χρήστης του μιλήσει το counter θα αυξάνεται αν είναι μικρότερο απο ο dialogue dictionary size έτσι ο χρήστης θα διαβάσει τον δεύτερο διάλογο όταν του ξαναμιλήσει. Όταν φτάσει το counter στο dictionary size δεν θα αυξάνεται περαιτέρω και ο χρήστης θα βλέπει συνέχεια το ίδιο dialogue. Επίσης πρέπει να το κάνω έτσι ώστε όταν ο χρήστης λαμβάνει το αντικείμενο απο τον χαρακτήρα ο χαρακτήρας να αλλάζει το αντικείμενο που πρέπει να δώσει στον χρήστη σε -1 ώστε να μην του το ξαναδίνει.
Επίσης θέλω να προσθέσω στους χαρακτήρες την δυνατότητα να μπορούν να παίρνουν αντικείμενα απο το χρήστη για τυχόν quests μπορεί να έχουν. Το inventory έχει την δυνατότητα να εξάγει αντικείμενα εαν υπάρχουν και να επιστρέφει true ή false αν τα πήρε ή όχι. Για τώρα έχω βάλει τα κομμάτια κειμένου στους διαλόγους για το να παίρνει ή όχι αντικείμενα: "TAKE_ITEM_{NUM}" το NUM θα έχει το id του αντικειμένου, όταν το βλέπει αυτό η συζήτηση βγάζει το take_item_ και θα πρέπει να στέλνει μύνημα στο UI οτι θέλει το αντικείμενο. Μετά το ui θα πρέπει να επιστρέφει μύνημα αν πήρε επιτυχως το αντικείμενο αυτό ή όχι , αν ναι θα προχωράμε στην επόμενη συζήτηση ενώ αν όχι θα παραμένει στην ιδια συζήτηση μέχρι να πάρουμε το αντικείμενο. Αν όμως η συζήτηση βρεί την λέξη "NOT_TAKE_ITEM" θα ξέρει οτι ο χρήστης δεν θέλει να δώσει το αντικείμενο και δεν θα προχωρήσει την συζήτηση. Για να γίνει αυτή η λειτουργικότητα έδωσα στον χρήστη το function Take_Item() που μπορεί να καλέσει ο χαρακτήρας δίνοντας το αντικείμενο που θέλει να πάρει ή το id και να λαμ΄βανει πίσω true ή false αν το πήρε. Η απάντηση true ή false ενημερώνει ένα variable που λέγεται move_on_dialogue το οποίο κανονικά θα είναι true ώστε ο χαρακτήρας να λέει κατι διαφορετικό μετα που μιλήσει με τον χρήστη αλλα θα γίνεται false αν ο χρήστης δεν δώσει αντικείμενο ή προσπαθήσει να δώσει αλλα δεν το έχει στο Inventory του.

Τωρα που τελειωσαμε με την λειτουργικοτητα του dialogue οταν κανει Interact μπορουμε να χρησιμοποιήσουμε όλα τα UI elements για να μπορουμε να δειξουμε στον χρήστη το inventory του και τον διαλογο και τις επιλογές του. Θα πρέπει τα ui elements να είναι αρκετα βασικά για τώρα και να έχουν μόνο ένα κείμενο και να δημιουργούν κουμπιά για κάθε επιλογή. Για τον σκοπό αυτόν θα υπάρχει ένα control item στην σκηνή που με κάποιον τρόπο θα συνδέεται με όλους τους χαρακτήρες και θα ακούει signals τους που όταν θα γίνονται θα ανοίγουν το dialogue ui, item inventory, options buttons κτλπ...
Το περιεχόμενο των διαλόγων περιέχεται ακόμα στον κάθε χαρακτήρα όμως τώρα έφτιαξα ένα control node που δρα σαν user interface και περιέχει ένα label στο κάτω μέρος στο οποίο θα βάζουμε το κείμενο των διαλόγων και απο πάνω του θα υπάρχουν κουμπιά για τις επιλογές του χρήστη αν έχει. Για τώρα αυτό το ui όταν δημιουργείται συνδέεται με τον χαρακτήρα του χρήστη αλλα και με τα npcs ώστε όταν ο χρήστης παίρνει ενα αντικείμενο να το μαθαίνει το UI παίρνοντας το item id σαν παράμετρο και όταν οι χαρακτήρες ξεκινάνε το conversation να λαμβάνει το κείμενο που λέει ο χαρακτήρας ώστε να το δείχνει στο label και αν υπάρχουν επιλογές να δημιουργεί κουμπιά που θα περιέχουν το κείμενο των επιλογών και αυτα να έχουν λειτουργικότητα. Όταν εμφανίζεται κείμενο για τον χρήστη κατα τον διάλογο έχοντας ή όχι επιλογές για να προχωρήση το παιχνίδι περιμένει από τον χρήστη να πατήσει το Interact κουμπί για να προχωρήσει ή αν υπάρχουν επιλογές να πατήσει μια επιλογή. Θα πρέπει όταν πατιούνται τα κουμπιά να ενημερώνεται ο χαρακτήρας για το τι κουμπί πατήθηκε και να προχωράει η κουβέντα.
Τωρα χρειαζόμαστε μόνο να δείχνουμε στον χρήστη ποιά αντικείμενα έχει πάρει, αυτό μπορεί να φαίνεται στο πλάι με συγκεκριμένα κουτάκια που περιέχουν το sprite του αντικειμένου. Χρησιμοποιώντας τις οδηγίες στην ιστοσελίδα https://codingquests.io/blog/godot-4-inventory-system-tutorial#going-further σκέφτηκα να αλλάξω το πώς λειτουργούν τα αντικείμενα μου. Αντί για κάθε αντικείμενο να κάνω ένα node, θα αφήσω το Node του interactable item και θα φτιάξω ένα resource που θα λέγεται item και το οποίο θα περιέχει κάποια values, αυτά τα values θα τα αρχικοποιούμε κατα την εκκίνηση του παιχνιδιού και θα τα αναθέτουμε σε κάθε interactable item που θα φτιάχνουμε στην σκηνή. Τότε εαν ο χαρακτήρας ή το αντικείμενο στο πάτωμα θέλουν να μεταφέρουν το αντικείμενο που περιέχουν στον χρήστη αντί για να μεταφέρουν ολόκληρο το node+script. Τα resources είναι ελαφριά και περιέχουν μόνο τα χαρακτηρισιτκά του αντικειμένου όπου πάνε, και στην περίπτωση μας θα έχουν name, description, id, type, max stack κτλπ. Έτσι όταν δίνουμε στον χρήστη ένα αντικείμενο θα είναι γρήγορο και απλό και θα μπορούμε πολύ εύκολα να αναφερόμαστε σε αυτό το αντικείμενο και τα χαρακτηριστικά του.
Χρησιμοποιώντας την λύση απο αυτή την σελίδα άλλαξα και τον τρόπο που δουλέυει το inventory. Τώρα το inventory μου αντι να είναι ένα array απο items έχει την δική του υπόσταση σαν instance. Το Inventory αυτό δημιουργείται στην αρχή του παιχνιδιού και δίνεται στον χρήστη και στο ui. Στον χρήστη για να προσθέτει ή να αφαιρεί αντικείμενα και στο ui για να ξέρει πότε θα γίνονται αλλαγές σε αυτό και να ενημερώνει τα γραφικά του. Επίσης το inventory θα περιέχει τον δικό του κώδικα για προσθήκη ή αφαίρεση αντικειμένων και επίσης θα έχει ένα signal που θα καλείται όταν αφαιρείται ή θα προστείθεται αντικείμενο. Ακόμη μέσα στο inventory αντι να περιέχονται αντικείμενα θα περιέχονται item slots τα οποία εκείνα θα περιέχουν αντικείμενα. Το έκανα αυτό διότι έτσι μπορούμε να βάλουμε στα slots ποσότητα αντικειμένου ώστε άν βάλουμε ένα αντικείμενο πάνω απο μια φορά να γίνεται stack. Τα inventory slots έχουνε και αυτά την δική τους υπόσταση. Με αυτόν τον τρόπο μπορούμε να μεταφέρουμε το instance του inventory πιο εύκολα και να μην το έχουμε περιορισμένο στον χρήστη απλά. Επίσης έδωσα τo function στο inventory να μπορεί να αλλάζει τη ποσότητα των inventory slots οποιαδήποτε στιγμή, προσθέτοντας slots ή αφαιρότνας αναλόγως με το πόσα θέλει ο δημιουργός του παιχνιδιού να έχει ο χρήστης. Δημιούργησα και ui inventory slots τα οποία θα εμφανίζονται στο επάνω μέρος της οθόνης. Περιέχουν ένα εικονίδιο και έναν αριθμό απο κάτω, το εικονίδιο θα είναι του αντικειμένου και ο αριθμός η ποσότητα του.

Μπορούμε να βάλουμε την δυνατότητα στον καθηγητή να μπορεί να αλλάζει το γραφικό στο inventory slot UI

Όλο το παιχνίδι θα παίρνει μέρος σε μία σκηνή, το main menu. Μέσα σε αυτό θα υπάρχει το Game Manager το οποιο θα δημιουργεί τα instances και θα τους δίνει τιμές απο το αρχείο Json που θα διαβάζει. Οπότε όταν ανοίγουμε το παιχνίδι στο ready το game manager θα διαβάζει το αρχείο και θα δημουργεί τα κουμπιά, τα οποία όταν πατηθούν θα ενημερώνουν το game manager να δημιουργήσει την πίστα που πάτησε ο χρήστης, θα δημιουργεί τους χαρακτήρες, τα αντικείμενα, τα quests κτλπ. ----------------------------

 Τώρα θα δημιουργήσω μία αρχική version του συστήματος πάλης βασισμένη στο βίντεο https://www.youtube.com/watch?v=ifXGvlAn0bY. Στο βίντεο υπάρχει στο φόντο ο εχθρός, κάτω η ζωή του χρήστη μαζί με το όνομα του, επάνω κείμενο για να ενημερώνει τον χρήστη ποιος είναι ο εχθρός που του επιτέθηκε, τι ζημία προκαλεί, τι ζημιά δέχεται και οταν νικάει, χάνει ή απογεύγει την μάχη, και πολύ βασικά animations χωρίς αλλαγή των sprite του χαρακτήρα. Στην μάχη δίνεται η δυνατότητα να επιτεθεί με μια βασική επίθεση προκαλώντας ζημιά με βάση την επίθεση του, όπου μετά θα δεχτεί ζημιά απο τον εχθρό, άμυνα που θα μειώσει την ζημιά της επόμενης επίθεσης του εχθρού σε 0 ( αν και μπορεί να μην χρειάζεται κάτι τέτοιο ) και η αποφυγή μάχης.
Πριν προσθέσω αυτήν την λειτουργία μάχης δημιούργησα ένα variable σε κάθε χαρακτήρα που θα έχει το όνομα του για να μπορούμε να το προσθέσουμε στους διαλόγους και στο combat panel και επίσης έφτιαξα ένα resource όπως το inventory το οποίο ονομάζεται combat stats που θα περιέχει οτιδήποτε χαρακτηριστικά δεν χρισημοποιούνται για διαλόγους ή κίνηση αλλά θα χρησιμοποιείται αποκλειστικά απο το νέο σύστημα μάχης και το έφτιαξα έτσι ώστε να μπορούμε να αλλάζουμε το πως δουλεύειτο combat ανεξάρτητα απο το υπόλοιπο σύστημα των χαρακτήρων. Έτσι τώρα όταν θα φτιάχνουμε τον χρήστη και τους άλλους χαρακτήρες θα δημιουργούμε ένα combat stats resource με τα εξής χαρακτηριστικά: health, attack_power, defense, speed το οποίο θα τους δίνεται, αλλά συγκεκριμένα για τους npc έχω και μία ακόμη variable με όνομα combatability το οποίο θα δείχνει στο σύστημα μάχης αν ο χρήστης μπορεί να ξεκινήσει μάχη με αυτόν το χαρακτήρα. Έπειτα θα φτιάξω μία ξεχωριστή σκηνή που θα περιέχει τα γραφικά μάχης και θα μπορεί να γίνει engaged απο κάθε χαρακτήρα κατά το interaction με τον χρήστη ή απο μόνοι τους αν τους έχουμε δώσει την ικανότητα να είναι aggresive που σε αυτή την περίπτωση θα τους βάλουμε να αναζητούν τον χρήστη όταν πάει κοντά τους και να ξεκινάνε το combat οταν τον πλησιάσουν. Όπως και αν γίνει θέλουμε όταν ο χρήστης και ένας χαρακτήρας ξεκινήσουν να αντιμετωπίζουν ο ένας τον άλλον ο game manager (ή για τώρα το stage) να δημιουργούν ένα instance της σκηνής μάχης και να δίνουν τα combat stats του καθενός χαρακτήρα στην σκηνή αυτή μαζί με το όνομα τους και το sprite τους. Η μάχη θα πρέπει να μπορεί να ξεκινήσει μετά από dialogue ή απλά κατά το interaction οπότε θα πρέπει να προσθέσουμε στον χαρακτήρα ένα σινιάλο που θα καλείται όταν πρέπει να αρχίσει η μάχη και θα συνδέεται με το scene manager το οποίο θα φτιαχνει την σκηνή μάχη και θα δίνει τα stats.
Ξεκίνησα τωρα να φτιάχνω την σκηνή μάχης, εκεί έχω προσθέσω ένα Control Node το οποίο θα περιέχει το παρασκήνιο που θα είναι ένα πεδίο με γρασίδι και μετά ένα margin container το οποίο μέσα θα έχει ένα Hbox και VBox container που θα περιέχουν τον αντίπαλο χαρακτήρα σε ένα δικό του Control Node ώστε να μπορεί να κεντραριστεί στην σκηνή κανονικά και ένα progress bar που θα είναι οι πόντοι ζωής του σε γραφική μορφή.
